目标交互 · 轮换与空闲重载

sequenceDiagram
 participant S as Server
 participant M as Mini
 participant C as 原生 CLI
 M->>S: 以 client_id 与激活证明登录
 S-->>M: 登录会话、授权线路、七天 Key 与服务端到期时间
 M->>C: 用户确认后写入网关配置
 M->>S: 到期前使用登录会话续领，重试复用轮换编号
 S-->>M: 下一代 Key 与到期时间
 M->>M: 新 Key 暂存钥匙串
 alt 活跃会话或活动状态未知
 M->>M: 显示等待空闲，保留现有配置
 else 已确认空闲
 M->>C: 校验配置版本，原子写入并按工具重载
 M->>S: 确认本代生效，旧代停止接受新请求
 end
 alt 旧 Key 已到期
 S-->>C: 新请求返回凭据已过期
 M->>M: 提示等待空闲或用户确认重新打开 CLI
 end

评审假设：七天由 Server 计时；已受理的流式响应允许完成。多个 CLI 共用一代 Key 时，Mini 等相关工具全部空闲再切换，逐工具记录写入结果，全部确认后退役旧代。历史会话文件不参与活跃判断。

场景预期
客户端改名 / 撤销单条线路历史按稳定 ID 关联；撤销后该线路的新请求被拒绝
离线到期 / 重复续领 / 配置被外部修改恢复网络后续领；相同轮换编号复用结果；配置冲突时停在待处理
